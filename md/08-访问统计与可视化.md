# 功能八：访问统计与可视化

## 一、访问计数

### 触发时机

访客每次进入简历首页，前端发送 `POST /api/visit`。后端：
1. 检查本次会话是否已经计过数（用一个内存 Set 存已记录的 Session ID）
2. 没计过才 +1，防止刷新页面反复计数
3. 同时记录来源 IP、来源 URL（referer）、访问页面、浏览器 User-Agent

### 数据库表

visit_log 表（每次访问一行）：
- id
- ip
- user_agent（浏览器 UA）
- referer（来源页面）
- page（访问的页面）
- visit_time（时间戳）
- share_link_id（如果是通过分享链接进来的，记录链接 ID）
- version_id（看到的简历版本）

### IP 定位

后端 `IpUtils` 工具类：
1. 从 request header 里依次取 `X-Forwarded-For`、`X-Real-IP`、`Proxy-Client-IP`、`HTTP_CLIENT_IP`（兼容各种反向代理）
2. 最后才从 `request.getRemoteAddr()` 取
3. 拿到 IP 后（本阶段只存不解析地理位置，可以接第三方 IP 定位 API 增强）

**知识点**：Nginx 反向代理后，后端 `request.getRemoteAddr()` 拿到的是 Nginx 容器 IP（127.0.0.1 或 Docker 内部 IP），不是真实访客 IP。Nginx 必须配置 `proxy_set_header X-Real-IP $remote_addr` 和 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for`，后端从这些 header 里取。

### 会话判断

后端用 `HttpSession.getId()` 做判重。访客浏览器不关闭的话 Session ID 不会变。后端有一个 `ConcurrentHashMap<String, Boolean>` 存已记录的 Session ID，定期清理（过期 Session 从 Map 移除）。

**为什么不用 Redis**：单实例部署，内存 Map 足够。如果以后多实例，换成 Redis Set 即可。

## 二、后端统计接口

### 总览数据

`GET /api/admin/visit/summary` 返回：
- 总访问次数
- 今日访问次数
- 本周访问次数
- 本月访问次数
- 今日独立 IP 数
- 活跃分享链接数

### 时间维度数据

`GET /api/admin/visit/trend?days=30` 返回最近 N 天每天的访问次数：
```json
[
  {"date": "2024-06-01", "count": 23, "uniqueIps": 15},
  {"date": "2024-06-02", "count": 18, "uniqueIps": 12},
  ...
]
```

SQL 大概是：
```sql
SELECT DATE(visit_time) AS date,
       COUNT(*) AS count,
       COUNT(DISTINCT ip) AS uniqueIps
FROM visit_log
WHERE visit_time >= CURDATE() - INTERVAL #{days} DAY
GROUP BY DATE(visit_time)
ORDER BY date ASC
```

### 来源分布

`GET /api/admin/visit/sources?top=10` 返回 top 来源：
```sql
SELECT referer, COUNT(*) AS count
FROM visit_log
WHERE referer IS NOT NULL AND referer != ''
GROUP BY referer
ORDER BY count DESC
LIMIT 10
```

### 分享链接访问排名

`GET /api/admin/visit/links-rank` 返回每个分享链接的访问次数。

## 三、前端 ECharts 可视化

**文件**：`frontend/src/views/admin/Dashboard.vue`

### 折线图：访问趋势

```javascript
import * as echarts from 'echarts'
const chartRef = ref(null)

onMounted(() => {
  const chart = echarts.init(chartRef.value)
  chart.setOption({
    title: { text: '访问趋势（近30天）' },
    tooltip: { trigger: 'axis' },
    xAxis: { type: 'category', data: trend.dates },  // ["06-01", "06-02", ...]
    yAxis: { type: 'value' },
    series: [
      { name: '访问次数', type: 'line', smooth: true, data: trend.counts },
      { name: '独立 IP', type: 'line', smooth: true, data: trend.uniqueIps }
    ]
  })
  // 窗口大小变化时 resize
  window.addEventListener('resize', () => chart.resize())
})
```

### 饼图：来源分布

```javascript
chart.setOption({
  tooltip: { trigger: 'item' },
  legend: { bottom: '5%' },
  series: [{
    type: 'pie',
    radius: ['40%', '70%'],     // 环形图，内半径 40% 外半径 70%
    data: sources.map(s => ({ name: s.referer, value: s.count }))
  }]
})
```

### ECharts 的关键点

- `echarts.init(dom)` 在指定 DOM 容器上初始化图表
- `setOption(option)` 是配置驱动的，改 option 就行，不用改 DOM
- `tooltip: { trigger: 'axis' }` 折线图鼠标悬停显示整条垂直轴的数据
- 窗口 resize 时必须手动调 `chart.resize()`，否则图表不会自适应

## 四、知识点总结

| 知识点 | 说明 |
|--------|------|
| POST /api/visit | 访客进入时前端发一次，后端 Session 判重后才 +1 |
| X-Forwarded-For | Nginx 反代后后端取真实 IP 的标准 header，多个 IP 逗号分隔 |
| ConcurrentHashMap 判重 | 单实例场景够用，Session ID 作为 key，定期清理 |
| DATE() + GROUP BY | H2 MySQL 兼容模式下 `DATE(visit_time)` 按天聚合，写法和 MySQL 一致 |
| COUNT(DISTINCT) | 独立 IP 计数，去重 |
| ECharts init + setOption | 配置驱动的图表 API，option 对象描述所有视觉属性 |
| echarts.resize() | 必须手动响应窗口变化，ECharts 不会自动监听 |
| 折线 smooth: true | 平滑曲线，视觉上更自然 |
| 环形饼图 radius | 传数组 `[inner, outer]` 就是环形，只传一个数就是实心圆 |
