# 08 后台管理

后台是 11 个页面共用一套骨架：左侧菜单容器 + 顶栏 + 内容区，内容区里再分「跟版本走的内容页」和「不跟版本走的归档页」两类。这一篇记录骨架怎么搭、版本作用域怎么贯穿、CRUD 页的共同代码形状，以及各页面的差异点。

## 骨架：AdminLayout

`layouts/AdminLayout.vue` 是 `/admin` 的父路由组件（`router/index.js:36-38`），带 `redirect: '/admin/dashboard'`。

菜单项由路由表派生，不是另一份数组（`AdminLayout.vue:128-134`）：

```js
const menuItems = router.getRoutes()
  .find((r) => r.path === '/admin')
  .children.map((child) => ({
    path: `/admin/${child.path}`,
    title: child.meta.title,
    icon: child.meta.icon
  }))
```

顺序即路由 children 的声明顺序，11 项：数据概览 / 基本信息 / 教育经历 / 工作项目 / 技能管理 / 荣誉证书 / 作品集 / AI 问答记录 / 简历版本 / 专属链接 / 主题与站点（`router/index.js:40-105`）。title 和 icon 只在路由 `meta` 里写一份，顶栏标题读的也是同一个来源（`route.meta.title`，`AdminLayout.vue:55`），新增页面只要在 children 里加一条，菜单和顶栏一起生效。代价是菜单顺序完全跟 children 顺序绑定，想调整菜单就得挪路由声明。

`el-menu` 开了 `router` 属性（`:23`），点击菜单项直接按 `index`（也就是 path）路由跳转，不需要写 click 处理；`@select="mobileMenuOpen = false"`（`:28`）负责点完菜单关抽屉。`background-color="transparent"` 配 `text-color` / `active-text-color`，实际配色由 `styles/admin-responsive.css` 和 scoped 样式里的 `:deep(.side-menu .el-menu-item)`（`:183-195`）承担。

移动端的处理是这个文件里最绕的一段，原因是「折叠」和「抽屉」是两个互不相干的状态：

```js
const collapsed = ref(false)          // 桌面侧栏折叠
const mobileMenuOpen = ref(false)     // 移动抽屉
const mq = window.matchMedia('(max-width: 768px)')
const menuCollapsed = computed(() => (isMobile.value ? false : collapsed.value))
```

`:105-120`。断点 768px 写了两遍（JS 里的 matchMedia 和 `admin-responsive.css` 的媒体查询），`:108` 的注释就是提醒这两处要人工保持一致。抽屉打开时强制 `menuCollapsed = false`，否则 64px 宽图标抽屉看不到文字；回到桌面端时 `onMqChange` 主动关掉可能残留的抽屉（`:114`）；路由变化也关（`:123-125`）；`onUnmounted` 移除监听（`:117`）。遮罩层是模板最前面那个 `v-if="mobileMenuOpen"` 的 div（`:4-8`）。

侧栏宽度用三元绑定 `:width="collapsed ? '64px' : '220px'"`（`:10-11`），`logo-text` 用 `v-if="!menuCollapsed"`（`:17`）。

顶栏右侧的退出走 `handleCommand('logout')`（`:136-146`）：先 `ElMessageBox.confirm`，确认后才调 `userStore.logout()`，再跳 `/login`。

## 登录态：三键 localStorage + Pinia

`store/user.js:5-9` 的 state 初值直接从 localStorage 读：

```js
token: localStorage.getItem('token') || '',
username: localStorage.getItem('username') || '',
nickname: localStorage.getItem('nickname') || ''
```

没有持久化插件，靠 `login()` 写入三键（`:20-22`）、`reset()` 删三键（`:36-38`）。刷新页面时 Pinia 重建，初值又把登录态捞回来，代价是 `isLoggedIn`（`:11`）只判断 token 存在与否，不判断是否过期——真正判定在服务端，401 由 `utils/request.js` 兜住并触发清理。

`logout()` 里对后端调用包了 try/catch 且 catch 为空（`:24-31`）：后端 `/api/auth/logout` 本身是无状态空实现（第 02 篇），网络失败也不能卡住前端清理。登录页 `views/admin/Login.vue:10-46` 有 `rules` 校验、`loading` 态、失败提示，成功后按 `query.redirect` 回原页面。

## 版本作用域贯穿所有编辑页

`composables/useVersionScope.js` 只有 26 行，但决定了后台所有页面的行为边界：

```js
const res = await getVersions()
versions.value = res.data || []
if (selectId) currentVersionId.value = selectId
else if (!currentVersionId.value || !versions.value.some((v) => v.id === currentVersionId.value)) {
  const def = versions.value.find((v) => v.isDefault === 1) || versions.value[0]
  currentVersionId.value = def ? def.id : null
}
```

`:12-21`。回落链是「显式指定 → 当前值仍存在于列表 → 默认版本 → 列表首项 → null」。最后那层 `|| versions.value[0]` 是给「没有默认版本」的异常数据兜底；`null` 时各页面的 `loadList()` 直接 return（如 `EducationManage.vue:120`），新增按钮也 `:disabled="!currentVersionId"`（`:9`）。

`onMounted(() => loadVersions())` 写在 composable 内部（`:23`），所以页面只要 `const { versions, currentVersionId } = useVersionScope()`（`EducationManage.vue:95`）就自动加载版本列表，不需要各自记得调。

要点：`currentVersionId` 只活在内存里，没有写 localStorage，也没有同步到 URL。刷新后台页面会重新落回默认版本；从「简历版本」页跳走再回来，选中版本也会丢。

`components/admin/VersionBar.vue` 是各编辑页顶部的公共条：一个 240px 的 `el-select`（`:9`）+「预览该版本」按钮（`:21-23`）。组件本身只 `defineProps({ modelValue, versions })` 并 `emit('update:modelValue')`（`:30-39`），没有任何请求逻辑，也不额外发 `change` 事件——页面靠 `watch(currentVersionId)` 重新拉列表（`EducationManage.vue:161`），多一个事件源只会让同一次切换发两遍请求。预览是 `window.open('/#/?versionId=' + modelValue, '_blank')`（`:41-45`）——hash 路由下这条 URL 会新开标签页渲染首页，配合 `ResumeHome.vue:51-62` 的版本提示条。没有「在此设为默认」按钮，设默认只在「简历版本」页做（第 03 篇）。

## CRUD 页的共同形状

以 `EducationManage.vue` 为样本，每个内容页都是同一套 10 步：

| 步骤 | 位置 | 说明 |
|------|------|------|
| VersionBar 绑 currentVersionId | `:3` | 只有 `v-model`，列表由下面的 watch 触发 |
| 工具栏「新增」按钮 | `:9` | `:disabled="!currentVersionId"` |
| el-table 列表 + 编辑/删除 | `:15-31` | 只读展示，不排序 |
| 单个 el-dialog 复用新增/编辑 | `:34` | `:title="form.id ? '编辑…' : '新增…'"` |
| el-form + rules + formRef | `:35` | 校验字段较少 |
| `emptyForm()` 工厂 + `reactive` | `:102-113` | 一份形状，两个场景都用 |
| `openDialog(row)` | `:130-133` | `Object.assign(form, emptyForm(), row ? {...row} : {})`，随后强制 `form.versionId = currentVersionId.value` |
| `save()` | `:136-148` | `await formRef.value.validate()` → 按 `form.id` 决定 put/post → 关弹窗 → `loadList()` 重拉 |
| `remove(row)` | `:154-159` | `ElMessageBox.confirm` → delete → `loadList()` |
| 版本变化重新拉列表 | `:161` | `watch(currentVersionId, () => loadList(), { immediate: false })` |

几个刻意的选择：

- **不本地更新，保存后重拉**。`save()` 成功后 `loadList()`（`:148`），列表以服务端为准，sort/时间戳等由后端算的字段能立刻反映出来。代价是每次保存一次往返。
- **一份 dialog 走新增和编辑**。判定用 `form.id` 是否存在，因此 `emptyForm()` 必须把 `id` 也清掉（`:102-113`），否则新增会带上前一条的 id 变成更新——这是这套形状里最容易改坏的一处。
- **排序是手工数字**。`el-input-number`（`:69`，范围 0~9999）直接填 `sort`，没有拖拽，也没有 move/reorder 接口，和后端「sort 不自增、顺序由 sort + id 决定」是同一个决定的两端（第 03 篇的排序表）。

版本切换只有一条触发路径：`VersionBar` 用 `v-model` 改写 `currentVersionId`（`:3`），页面靠 `watch(currentVersionId, loadList)`（`:161`）重拉列表，组件本身不再发 `change`，一次切换只有一次请求。用 `useVersionScope()` 的四个页面（`EducationManage.vue`、`SkillManage.vue`、`ExperienceManage.vue`、`ProfileEdit.vue`）都在第 3 行挂同一个组件；`HonorManage.vue`、`PortfolioManage.vue` 按归属人管理，不引这个组件。

## 各页面的差异

**工作/项目**（`ExperienceManage.vue`）在 VersionBar 右边多一组 `el-radio-group`（`:8-11`）切工作经历 / 项目经历，`@change="loadList"` 按 `activeType` 传 `type` 参数请求。表单里没有 type 字段——新增时由 `emptyForm()` 的 `type: 1`（`:99`）和保存时的 `type: activeType.value` 覆盖（`:126,134`），也就是说「在哪个 tab 里新增就是哪一类」，弹窗里改不了。这是把 type 从表单里移出去的做法，字段少了、歧义也少了。

**荣誉证书 / 作品集**（`HonorManage.vue:3-19`、`PortfolioManage.vue:3-19`）顶部不是 VersionBar 而是一个归属人选择器（`el-select` 遍历 `owners`），配一句固定提示「同一人名下的所有简历版本共享这里的荣誉/作品」。owners 候选来自 `service/OwnerService.java` 的聚合接口（第 03 篇）。这两个页面因此不受版本切换影响，改的是 `owner_name` 维度。荣誉用 `el-table` + `el-image` 预览（`HonorManage.vue:36-40`），作品集用 `el-row/el-col` 响应式网格（`PortfolioManage.vue:33-49`，`:xs=24 :sm=12 :lg=8`）配封面图上传（`:59-70`），空态用整行 `el-col :span=24`（`:52`）。

**基本信息**（`ProfileEdit.vue`）是这套骨架里唯一没有 `rules`、没有 `validate()` 的表单（`:6-11` 的 el-form 没有 `:rules`，`save()` 在 `:164-172` 直接提交）。理由说得通：个人信息每个字段都可以留空，必填校验反而会把人挡住；风险是 `name` 改空会连带荣誉证书和作品集的归属口径一起变（这两个页按 `owner_name` 查）。头像走 `el-upload` 自定义 `:http-request`（`:14-31`，`handleUpload` 在 `:140-148`），删除按钮只把 `form.avatar` 置空串并提示「点击保存修改」（`:150-162`），保存时再把空串转成 `null`（`:169`）——因为后端需要区分「不改」和「清空」，空串不会被当成清空。

**主题与站点**（`ThemeSetting.vue`）只编辑 `site_config` 三个字段：站点标题、默认主题（radio）、AI 问答开关。AI 开关是 `tinyint 0/1`，表单里用 `computed` 适配器转成布尔（`:98-101`）：

```js
get: () => form.aiEnabled === 1,
set: (v) => { form.aiEnabled = v ? 1 : 0 }
```

右侧有一张预览卡，直接在局部元素上写 `:data-theme="form.defaultTheme"`（`:56`），不用保存就能看到配色——这是主题机制（`data-theme` 属性 + CSS 变量，见第 06 篇）顺带带来的好处。页面底部还有一个「刷新缓存」按钮（`:72`），调 `POST /api/admin/cache/refresh`，对应第 05 篇的资源指纹服务。

**简历版本**（`VersionManage.vue`）是表格 + 三个操作（重命名 / 设为默认 / 删除，`:31-46`）+ 创建弹窗（`:50-76`），另外把「PDF 导入」做成页头的按钮开一个独立弹窗（`:7,79-143`），不是后台菜单项。导入弹窗用 `el-upload` 且 `:auto-upload="false"`（`:88-91`），配 `uploadPct` 进度条（`:105-107`），提示文案写明「仅支持文字版 PDF，单文件不超过 10MB；扫描件/纯图片 PDF 无法识别」（`:101`）——这条限制和后端 `ResumeImportService` 的空文本处理是同一件事的两面（第 05 篇）。

**AI 问答记录**（`AiHistory.vue`）分页 `size = 10`（`:76`），列表里 sessionId 截前 12 位显示（`:25`），来源用 tag 区分「大模型 / 本地问答」（`:39-41`），只有单条删除（`:49`），没有清空全部。

**专属链接**（`ShareLinkManage.vue`）生成表单只有备注、绑定版本、过期时间、最大次数四项，备注是唯一必填（`rules` 在 `:136`）。过期时间下面固定一句提示：「这里控制的是链接本身的有效期；访客换到的登录态另有固定时长（后端默认 60 天），到期后重新点链接即可」（`:92-94`），避免把令牌有效期和链接有效期混为一谈。分享 URL 在前端拼：`${window.location.origin}/#/r/${token}`（`:205-207`）——所以同一个链接从后台复制出来的地址取决于当前访问后台用的域名。复制走两条路（`:215-233`）：`navigator.clipboard` 且 `window.isSecureContext` 才用异步 API，否则退回临时 textarea + `document.execCommand('copy')`，因为 http 部署下 clipboard 不可用。列表的失效状态也在前端判：`row.maxViews && row.viewCount >= row.maxViews`（`:149`）、`row.expireTime` 与当前时间比较（`:153-158`，比较前把 `-` 换成 `/` 以避开 Safari 对 `yyyy-MM-dd HH:mm:ss` 的解析差异）。吊销是 `PUT` 更新 `enabled=0`，按钮对已吊销行 `:disabled="row.enabled !== 1"`（`:60`），确认框文案强调「不可恢复」（`:196`）。

## 后端侧的接口分布

17 个控制器（`backend/src/main/java/com/example/resume/controller/`）里，管理端路径有两种写法：

```java
@RequestMapping("/api/admin/versions")   // VersionController.java:22，类级写全
@RequestMapping("/api")                  // EducationController.java:17 等，方法级再写 /admin/educations
```

`/api` + 方法级 `/admin/**` 是多数（Profile/Education/Experience/Skill/Honor/Portfolio/ShareLink/Ai/Config/Upload），类级写全是 6 个（Auth、Cache、Import、Owner、Stats、Version）。两种都能跑，安全配置里的匹配规则也统一按 `/api/admin/**` 拦（`config/SecurityConfig.java:49-82`，第 02 篇），只是查接口时得注意别按前缀猜文件。

## 可复用点

- **作用域 composable 把「挂载即加载」和回落链都吃掉**：`useVersionScope()` 内部就写了 `onMounted(() => loadVersions())`（`composables/useVersionScope.js:23`），页面解构一行就完成初始化，不存在"某个页面忘了调"；回落链是显式指定 → 当前值仍在列表 → 默认版本 → 列表首项 → null（`:12-21`），当前版本被删掉时自动落回默认。null 这一层由页面各自收口：列表函数首行 return（`EducationManage.vue:120`）、新增按钮 `:disabled`（`:9`）。任何"页面级作用域 + 候选列表"（租户、环境、数据集、语言版本）都能套这个形状。要注意的坑是 `versions.value[0]` 这层兜底会让"没有默认版本"这种异常数据仍可编辑，一旦作用域本身有唯一性约束，页面侧就不该再猜一个。
- **一份表单两种模式必须由 `emptyForm()` 保证 id 被清**：判定走 `form.id ? put : post`（`EducationManage.vue:136-148`），编辑走 `Object.assign(form, emptyForm(), row)`，因此工厂函数里没有 `id` 字段就等于给新增带上前一条的 id，变成静默改数据。这一处是十步形状里最容易改坏的，`emptyForm()` 与表单字段必须一起维护（`:102-113`）。同一形状还有两条约定值得原样抄：保存成功后重拉列表而不是本地更新（后端算出的 sort、时间戳立刻可见，代价是一次往返）；枚举型字段从弹窗里移出去，用工具栏的 tab 决定（`ExperienceManage.vue:99,126,134`），字段少一个，歧义也少一个。
- **无持久化插件的登录态：state 初值就是 localStorage**：`token / username / nickname` 三键在 store 构造时读入（`store/user.js:5-9`），`login()` 写三键（`:20-22`）、`reset()` 删三键（`:36-38`）。刷新时 Pinia 重建、初值把登录态捞回来，不需要插件，也不需要路由守卫读存储以外的东西。`isLoggedIn` 只判存在（`:11`），过期判定完全交给服务端 + 401 拦截器，前端不复制一份有效期规则。反过来也提醒一句：登出调后端要包 try/catch 且 catch 为空（`:24-31`），无状态接口失败不该阻塞本地清理。
- **「不改 / 清空」在前端要有一个明确的表达**：`ProfileEdit.vue` 删头像只把 `form.avatar` 置空串（`:150-162`），保存时 `if (!payload.avatar) payload.avatar = null`（`:169`），空串转 null 才让后端区分"这次没动"和"要清空"——配合实体上的 `FieldStrategy.IGNORED` 才是完整一条链（第 03 篇）。同理 `site_config.ai_enabled` 是 `tinyint 0/1`，表单用 `computed` 适配器转布尔（`ThemeSetting.vue:98-101`），开关组件不用改、后端字段类型也不用改。预览则把主题机制挪用到局部：`:data-theme="form.defaultTheme"` 写在预览卡上（`:56`），不保存就能看配色。三处都是"两种语义挤在一个字段值里"时的拆法。
- **两个必须降级/绕行的浏览器行为**：剪贴板先判 `navigator.clipboard && window.isSecureContext`，不满足退回临时 textarea + `document.execCommand('copy')`（`ShareLinkManage.vue:215-233`），http 部署下异步 API 直接不可用；日期串比较前把 `-` 换成 `/`（`:153-158`），Safari 对 `yyyy-MM-dd HH:mm:ss` 形式的 `new Date()` 解析结果与其他浏览器不同。这两条在任何"后台列表显示状态"的页面都会撞到，判定放前端就要连这两处一起抄；更彻底的解法是让服务端直接返回状态字段。
