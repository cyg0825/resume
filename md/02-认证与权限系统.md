# 功能一：认证与权限系统

## 功能概述

简历网站的认证体系解决两个问题：

1. **后台管理**：管理员用户名密码登录，拿到 JWT，后续请求自动携带。
2. **私密分享**：访客通过专属链接（带随机 token）换取短期访客 JWT，之后就能只读访问简历内容。

后端用 Spring Security + JWT 实现，前端用 axios 拦截器自动处理两个令牌的携带和 401 失效跳转。

---

## 一、JWT 是什么

JWT（JSON Web Token）是一种开放标准，把用户信息编码成一个字符串。格式是三段用 `.` 分隔的 Base64：

```
Header.Payload.Signature
```

- Header：声明类型和签名算法，比如 `{"alg":"HS256","typ":"JWT"}`
- Payload：自定义数据（claim），比如 `{"sub":"admin","userId":1,"exp":1735689600}`
- Signature：用密钥对前两段签名，防止篡改

服务端只需要保存密钥，不需要像 Session 那样在服务器存储状态。JWT 本身携带了用户信息，服务端解析完就知道"这是谁"。

### 什么是 claim

claim 就是 Payload 里的字段。JWT 规范了几个标准 claim：
- `sub`（subject）：主题，通常存用户名
- `iat`（issuedAt）：签发时间
- `exp`（expiration）：过期时间

除此之外，还可以放自定义 claim。本项目里管理员令牌放了 `userId`，访客令牌放了 `kind=share`、`linkId`、`versionId`。

### 签名算法

HS256（HMAC-SHA256）是对称加密：签发和校验用同一个密钥。密钥在配置文件里通过环境变量 `JWT_SECRET` 注入。

## 二、后端 JWT 工具类（JwtUtil）

**文件**：`backend/src/main/java/com/example/resume/security/JwtUtil.java`

### 两个生成方法

管理员令牌：
```java
generateToken(Long userId, String username)
// claim: subject=username, userId=xxx, iat, exp(默认 60 天)
```

访客令牌：
```java
generateShareToken(Long linkId, Long versionId)
// claim: subject="share-" + linkId, kind="share", linkId=xxx, versionId=xxx(可选), iat, exp
// 有效期默认 60 天
```

### 解析方法

```java
Claims parse(String token)
// 用配置的密钥校验签名，校验通过返回 Claims 对象
// 校验失败（过期、篡改、格式错误）返回 null，不抛异常
```

### 密钥初始化

用 `@PostConstruct` 注解的 `init()` 方法在 Spring Bean 创建后把配置的字符串密钥转成 `SecretKey` 对象，用的是 HMAC 对称密钥的标准构造：

```java
this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
```

**知识点**：`@PostConstruct` 是 Java EE 的生命周期注解，在依赖注入完成后自动执行一次。适合做只执行一次的初始化逻辑。

## 三、自定义 JWT 过滤器

**文件**：`backend/src/main/java/com/example/resume/security/JwtAuthenticationFilter.java`

这个过滤器继承了 `OncePerRequestFilter`（Spring 保证每个请求只执行一次），核心逻辑：

```
doFilterInternal(request, response, filterChain):
  1. 从 request header 取 Authorization
  2. 检查是否以 "Bearer " 开头
  3. 取 token 部分，调用 jwtUtil.parse() 解析
  4. 解析成功 → 构建 Authentication 对象 → 放入 SecurityContext
  5. filterChain.doFilter() 放行
```

### 管理员 vs 访客的差异处理

解析出的 Claims 里如果有 `kind=share`，说明是访客令牌：

- 额外检查分享链接的状态（是否被吊销、是否过期、访问次数是否超限）
- 用 `ROLE_VISITOR` 权限，主体是 `SharePrincipal(linkId, boundVersionId)`
- 访客令牌里携带的 `versionId` 是链接绑定的版本号，后端会强制访客只能看这个版本

管理员令牌：
- 没有 `kind` claim，直接视为管理员
- 用 `ROLE_ADMIN` 权限，主体是用户名

### 关键设计

**防越权**：访客令牌每次请求都会回查分享链接的数据库状态。如果管理员把链接吊销了（`enabled=0`）或过期了，过滤器发现后不设置 Authentication，直接放行到 Spring Security 的后续过滤器链，Security 发现需要认证就返回 401。这样吊销操作能即时生效。

**知识点**：`SecurityContextHolder.getContext().setAuthentication(authentication)` 是 Spring Security 的核心 API。后续所有代码（Controller、Service 层）都可以从这里取出当前登录用户。`authentication.getPrincipal()` 可以拿到主体（管理员是 String 用户名，访客是自定义的 SharePrincipal 对象）。

## 四、Spring Security 配置

**文件**：`backend/src/main/java/com/example/resume/config/SecurityConfig.java`

### 禁用 CSRF

```java
.csrf(AbstractHttpConfigurer::disable)
```

**知识点**：CSRF（跨站请求伪造）保护基于 Cookie 的 Session 机制（浏览器自动带 Cookie）。本项目用 JWT，令牌存在 localStorage 里，需要手动放到 Authorization 头，不存在浏览器自动携带的问题，所以 CSRF 保护可以关掉。

### 无状态 Session

```java
.sessionManagement(session ->
    session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
```

告诉 Spring Security 不要创建任何 HttpSession。一切认证状态都在 JWT 里。

### URL 权限匹配

```java
.authorizeHttpRequests(auth -> auth
    .requestMatchers("/doc.html", "/v3/api-docs/**", ...).permitAll()
    .requestMatchers("/api/auth/**", "/api/share/access").permitAll()
    .requestMatchers("/uploads/**").permitAll()
    .requestMatchers(HttpMethod.GET, "/api/profile", "/api/educations", ...)
        .hasAnyRole("ADMIN", "VISITOR")
    .requestMatchers(HttpMethod.POST, "/api/visit", "/api/ai/chat")
        .hasAnyRole("ADMIN", "VISITOR")
    .requestMatchers("/api/admin/**").hasRole("ADMIN")
    .anyRequest().denyAll())
```

从上到下匹配，先匹配先生效。关键点：

- `/uploads/**` 是静态图片目录，`<img>` 标签无法携带 Authorization 头，所以必须公开
- 简历只读接口（GET `/api/profile` 等）用 `hasAnyRole("ADMIN", "VISITOR")`，同时允许管理员和访客
- 后台写接口（`/api/admin/**`）只允许 `ROLE_ADMIN`
- 最后兜底 `anyRequest().denyAll()`，拒绝所有没明确放行的请求

### 401 / 403 统一 JSON 返回

```java
.exceptionHandling(ex -> ex
    .authenticationEntryPoint(...)   // 未认证 → 401
    .accessDeniedHandler(...))        // 已认证但权限不足 → 403
```

默认情况下 Spring Security 返回 HTML 登录页或默认错误页。这里自定义返回 `{code: 401, msg: "..."}` 格式的 JSON，前端可以直接解析。

### 过滤器链插入

```java
.addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class)
```

把自定义 JWT 过滤器插到 Spring Security 默认的表单登录过滤器**之前**执行。Spring Security 的过滤器链是一条链，每个请求从第一个过滤器开始依次通过。如果 JWT 过滤器已经在 SecurityContext 里放了 Authentication，后面的过滤器会发现"已经认证过了"，就跳过自己的认证逻辑。

## 五、登录接口

**文件**：`backend/src/main/java/com/example/resume/service/AuthService.java`

```java
login(LoginRequest request):
  1. 用 LambdaQueryWrapper 查 user 表，where username = ?
  2. BCryptPasswordEncoder.matches(明文, 数据库里的密文)
  3. 校验通过 → JwtUtil.generateToken(userId, username)
  4. 返回 LoginVO(token, username, nickname, avatar)
```

### BCrypt 是什么

BCrypt 是一种自适应哈希算法，自带盐值（salt）。同样的密码每次哈希出来的值不一样（因为随机盐），所以存的密文可以安全地放数据库。比单纯的 MD5/SHA-256 好得多——后者容易被彩虹表破解。

**知识点**：Spring Security 内置 `BCryptPasswordEncoder`。存密码时 `encoder.encode(明文)`，验密码时 `encoder.matches(明文, 密文)`。

### DataInitializer 兜底初始化

系统启动时 `DataInitializer.run()` 检查 user 表是否为空。为空时用配置的默认密码（`admin/admin123`）创建第一个管理员。密码存的是 BCrypt 密文。

## 六、分享链接体系（访客认证）

### 为什么需要分享链接

简历不想被搜索引擎索引，又想让特定人看到。生成一个带随机 token 的链接，发给对方。对方打开链接后服务端校验 token，返回一个短期有效的访客 JWT。之后访客的每次请求都用这个 JWT 认证。

### 生成链接（ShareLinkService.create）

```java
1. 生成 256 位安全随机数 → HexFormat 转 64 字符十六进制串作为 token
2. 创建 ShareLink 记录，存 DB：
   - token（链接的唯一标识）
   - remark（备注，比如"发往小红书的链接"）
   - versionId（绑定的简历版本，null 表示跟随默认版本）
   - expireTime（过期时间，可为 null 永不过期）
   - maxViews（最大访问次数，可为 null 无限）
   - viewCount（已访问次数）
   - enabled（1=启用，0=已吊销）
```

**知识点**：`SecureRandom` 是 Java 提供的密码学安全随机数生成器。生成 32 字节（256 位）的随机数，再用 `HexFormat.formatHex()` 转成十六进制字符串。这个空间大到无法暴力枚举（2^256）。

### 访问链接换取访客令牌（ShareLinkService.accessByToken）

```java
1. 用 token 查 share_link 表
2. 检查 enabled=1、expireTime 未过、viewCount < maxViews
3. 并发安全的访问次数 +1（用 update ... where id=? and view_count < maxViews 实现原子判断+自增）
4. generateShareToken(linkId, versionId) 生成访客 JWT
5. 返回 ShareAccessVO（包含访客令牌、版本信息、过期时间等）
```

**并发安全计数**：`incrViewIfValid` 这个自定义 Mapper 方法的 SQL 大概是：
```sql
UPDATE share_link SET view_count = view_count + 1
WHERE id = #{id} AND view_count < #{maxViews} AND enabled = 1 AND (expire_time IS NULL OR expire_time > NOW())
```
返回受影响行数。如果返回 0，说明已经不可用（超限/过期/被吊销），即使前一步 select 校验过也没用——并发场景下 select 和 update 之间可能已经被别人用光了。

### 吊销链接

把 `enabled` 字段置 0。由于 JWT 过滤器每次请求都会回查链接状态，吊销即时生效，已经拿到的访客令牌也会在下一次请求时被拦截。

## 七、前端令牌处理

### axios 请求拦截器

**文件**：`frontend/src/utils/request.js`

```
每次发送请求前：
  1. localStorage.getItem('token') → 管理员令牌存在？放 Authorization: Bearer <adminToken>
  2. 否则 → localStorage 里拿访客令牌 → Bearer <shareToken>
  3. 都没有 → 不设置 Authorization
```

管理员令牌优先。如果同时存在两个，永远用管理员令牌（因为管理员有权限访问一切）。

### 响应拦截器的 401 处理

```
收到 401：
  - 如果是管理员令牌失效 → 清除 localStorage.token → 跳转到 #/login
  - 如果是访客令牌失效 → 清除访客令牌 → 跳转到 #/blocked?reason=expired
  - 没有任何令牌却访问受保护内容 → 跳转到 #/blocked?reason=forbidden
```

### 路由守卫

**文件**：`frontend/src/router/index.js`

```
beforeEach:
  - /admin/** 需要登录态（localStorage.token 存在）
  - /login 如果已经登录 → 直接进 /admin/dashboard
  - meta.requiresShare 的页面（首页、荣誉详情）→ 需要管理员令牌或访客令牌
  - 都不满足 → 去 /blocked
```

用 `createWebHashHistory()` 模式，URL 形如 `http://example.com/#/`。好处：Nginx 配置时只需要给所有路径返回 `index.html`，刷新不会 404。

## 八、知识点总结

| 知识点 | 说明 |
|--------|------|
| JWT 结构 | Header.Payload.Signature 三段，Base64 编码，HMAC-SHA256 签名 |
| claim | Payload 里的字段，可以是标准的（sub、iat、exp）或自定义的（userId、kind、linkId） |
| Spring Security 过滤器链 | 请求依次经过多个 Filter，JWT 过滤器插在 UsernamePasswordAuthenticationFilter 之前 |
| SecurityContext | 线程级容器，存 Authentication 对象。后续代码随时可以 `SecurityContextHolder.getContext().getAuthentication()` |
| OncePerRequestFilter | Spring 保证每个 Servlet 请求只执行一次，避免异步转发时重复执行 |
| BCrypt | 自适应密码哈希，自带随机盐，适合存密码 |
| 并发安全更新 | 用 `UPDATE ... WHERE 条件` 实现原子性的"先判断再修改"，防止并发突破上限 |
| SecureRandom + HexFormat | Java 密码学安全随机数，生成不可枚举的分享链接 token |
| CSRF vs JWT | CSRF 保护基于 Cookie 自动携带的 Session；JWT 存在 localStorage，需要手动放 Header，所以不需要 CSRF 保护 |
| 吊销即时生效 | 虽然 JWT 本身无法中途吊销，但在过滤器里每次都查 DB 的链接状态，实现了即时吊销 |
| HashHistory | Vue Router 的 Hash 模式，URL 带 `#`，对服务器刷新友好 |
