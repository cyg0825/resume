# 01 整体架构与技术栈

## 这是个什么东西

部署在自有服务器上的简历网站，但不是一个公开页面。三条约束决定了后面所有设计：

1. 访客必须拿专属链接才能看到内容，链接可以设过期时间、访问次数上限，也可以随时吊销。
2. 同一份简历要维护多个版本（不同岗位方向各一份），内容按版本隔离。
3. 站长一个人维护，所以数据库内嵌、不需要独立进程，一条 compose 命令能起来。

由此展开的功能：双栏响应式简历展示、后台分模块编辑、版本克隆与默认切换、专属链接签发与吊销、访问统计、AI 问答（检索增强，未配置大模型时降级本地问答）、PDF 简历导入生成新版本、前端截图导出 PDF。

## 一次请求怎么走

```
浏览器
  │  hash 路由，静态资源由 Nginx 出
  ▼
Nginx (80)
  ├── /api/**     → backend:8080
  ├── /uploads/** → backend:8080
  └── 其余        → try_files 回 index.html
        │
        ▼
JwtAuthenticationFilter   只有 Authorization: Bearer 才解析，
        │                 且当前 Authentication 为空时才写入 SecurityContext
        │                 ← security/JwtAuthenticationFilter.java:38-42
        ▼
SecurityConfig URL 粒度判定  permitAll → 只读接口需 ADMIN 或 VISITOR → /api/admin/** 只 ADMIN
        │                 兜底是 denyAll，不是 authenticated  ← config/SecurityConfig.java:82
        ▼
Controller → Service → Mapper(BaseMapper) → H2 文件库
```

两种令牌互斥使用：管理员令牌由登录接口签发，访客令牌由专属链接换取。前端在一个请求里只会带一个，管理员令牌优先（`frontend/src/utils/request.js:11-25`）。

## 前后端之间的几个约定

响应体固定三字段 `{code, msg, data}`（`backend/src/main/java/com/example/resume/common/Result.java:13-15`），成功 `code=200 / msg="success"`，静态方法四个见 `Result.java:26-39`。

`code` 和 HTTP 状态码是两套口径，这一点必须记清，否则前端错误分支会写歪：

- 业务异常走 `BusinessException`，异常里的 code 只进 JSON body，HTTP 状态仍然是 200（`common/GlobalExceptionHandler.java:19-23`，方法上没有 `@ResponseStatus`）。所以"链接次数已达上限""默认版本不可删除"这类拒绝，在网络面板里看都是 200。
- 未认证与权限不足由 Spring Security 的两个 handler 直接写 response，HTTP 状态是真的 401/403（`config/SecurityConfig.java:85-99`）。前端只有这两类会触发跳转逻辑。

```java
// config/SecurityConfig.java:85-91 节选，401 的响应体
response.setStatus(401);
response.setContentType(MediaType.APPLICATION_JSON_VALUE);
response.setCharacterEncoding(StandardCharsets.UTF_8.name());
response.getWriter().write(objectMapper.writeValueAsString(
        Result.error(401, "访问凭证无效或已过期，请通过专属链接重新打开")));
```

`data` 为 null 时字段仍在，前端统一取 `res.data`。个别接口允许调用方自行处理错误提示，靠请求配置上的 `silentError` 标记跳过全局 ElMessage（`frontend/src/utils/request.js:33-35`），专属链接换取接口就是这个用法。

## 端口

开发：前端 5173（`frontend/vite.config.js:14`），`/api` 与 `/uploads` 代理到本机 8080（`vite.config.js:17-24`），所以开发时不存在跨域；后端 `server.port` 默认 8080，可用环境变量 `SERVER_PORT` 覆盖（`backend/src/main/resources/application.yml:7`）。

生产：Nginx 出 80，后端 8080 在 compose 里也做了宿主机映射，方便直接调接口，纯对外服务时可以去掉。

## 读代码的顺序建议

先看 `SecurityConfig` 和 `JwtAuthenticationFilter`，这两个文件划清了管理员与访客各自的可见范围，其余接口路径的命名都是从这里推出来的。然后看 `VersionService.resolveVersionId`，作为版本隔离的唯一入口，所有简历读写都要先过这一层。再往下 `AiService` 和 `ResumeImportService` 是两处外部依赖，可以最后看。

## 可复用点

- **两套状态码分工**：业务拒绝只改 JSON body、HTTP 保持 200（`common/GlobalExceptionHandler.java:19-23`），401/403 留给鉴权且由 Spring Security 直接写 response（`config/SecurityConfig.java:85-99`）。前端因此只需要两个错误分支：状态码跳转、业务码提示。换项目复用时先定这条分工，否则「登录过期」和「参数不合法」会在同一个 if 里打架。
- **菜单不维护第二份数据**：后台侧边栏直接由路由 children 生成（`layouts/AdminLayout.vue:128-134`），标题和图标只有 `meta` 一处来源（`router/index.js:35-107`）。新增页面漏配菜单这类问题从结构上消失，代价是菜单顺序、分组都得靠路由表表达。
- **请求级错误处理开关**：`silentError` 标记让个别接口跳过全局提示（`utils/request.js:33-35`），由调用方展示文案。适合「失败原因要渲染成页面状态」的入口，比如凭链接换取访问权；用多了就会变成错误提示不一致，所以只给这一类接口开。
- **对称密钥的长度约束要提前吸收**：`Keys.hmacShaKeyFor` 在 Bean 初始化阶段抛 `WeakKeyException`，堆栈不指向密钥长度（`security/JwtUtil.java:34-37`）。占位默认值本身不安全，但必须满足 ≥32 字节，否则连本地零参数启动都起不来（`application.yml:67-70`）。任何带密钥强度校验的组件都适用这条：默认值先保证「能启动」，安全性由环境变量覆盖来保证。
- **私密站点的托管取舍**：hash 路由（`router/index.js:112`）+ Nginx 一条 `try_files` 回退，静态托管不需要任何服务端路由配置，也不会在爬虫路径上留下可遍历的真实 URL。代价是 URL 里带 `#`、分享链接不够干净，这是「不想被索引」优先于「链接好看」的选择。
