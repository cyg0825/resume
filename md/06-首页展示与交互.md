# 06 首页展示与交互

前台只有一个页面承载全部简历内容，另外三个页面负责「进得来 / 进不来 / 看得懂单张证书」。这一篇记录路由与拦截、首屏数据加载、板块显隐的判定口径、滚动相关的三个交互（入场动画、导航高亮、侧栏吸顶）、主题切换的实现层次，以及响应式重排的做法。

## 路由与访问拦截

`frontend/src/router/index.js:3-108` 是全部路由：5 个独立页面（首页、入口页、拦截页、证书详情、登录）+ 1 个后台父路由带 11 个子路由 + 1 条兜底重定向。

| 路径 | 组件 | meta |
|------|------|------|
| `/` | `views/home/ResumeHome.vue` | `requiresShare: true` |
| `/r/:token` | `views/home/ShareEntry.vue` | — |
| `/blocked` | `views/home/BlockedHome.vue` | — |
| `/honor/:id` | `views/home/HonorDetail.vue` | `requiresShare: true` |
| `/login` | `views/admin/Login.vue` | — |
| `/admin` + 11 个子路由 | `layouts/AdminLayout.vue` | 各带 title 与 icon |
| `/:pathMatch(.*)*` | 重定向到 `/` | — |

history 用的是 `createWebHashHistory()`（`router/index.js:112`）。这一点和「私密」直接相关：Nginx 只需要把 `index.html` 兜住，任何 `#/xxx` 路径都不会产生额外的服务端路由需求；`scrollBehavior` 只写了一件事——每次跳转滚回顶部（`:114-116`），页面内的定位全靠手动 `scrollIntoView`。

全局守卫在 `router/index.js:122-140`，三条规则按顺序生效：

1. `/admin` 开头且没有 `localStorage.token` → 跳 `/login`，并把 `to.fullPath` 放进 `query.redirect`。
2. 已登录还访问 `/login` → 直接 `/admin/dashboard`。
3. `meta.requiresShare` 且既没有管理员 token 也没有 `resume-share-token` → 跳 `/blocked?reason=forbidden`。

规则 3 的判定只看「有没有令牌」，不看令牌有没有过期。过期是请求发出之后由后端返回 401 才处理的，所以直接访问 `/#/` 会先渲染首页骨架、请求失败后被 `utils/request.js` 的 401 分支踢回拦截页；这一串行为在第 02 篇里对着拦截器逐行写过。

## 专属链接的入口页

`/r/:token` 是唯一给访客的入口，逻辑全在 `views/home/ShareEntry.vue:34-46`：

```js
const res = await accessShareLink(route.params.token)
saveShareAccess(res.data || {})
router.replace('/')
```

成功就存凭证并 `replace` 到首页——用 replace 是为了不让入口页留在历史里，否则访客点返回会停在「正在打开简历…」这一屏。失败分支里 `errorMsg` 先显示 900ms，然后 `router.replace({ path: '/blocked', query: { reason } })`，中间那 900ms 只是给一个「无法打开简历」的提示留个肉眼可见的时间。

`reason` 由后端返回的业务子码推出（`ShareEntry.vue:25-32`：4031 → expired、4032 → views、429 → limit，其余 invalid）。四个子码定义在 `service/ShareLinkService.java:38-41`，文案与码解耦，后端改提示不影响拦截页分支。

拦截页 `views/home/BlockedHome.vue:31-54` 有 5 组文案，键正好是 `invalid / expired / views / limit / forbidden`，取不到键就落到 `forbidden`。页面本身不含任何简历数据，只有一个「管理入口」的 `router-link` 指向 `/login`。

5 组文案之上还有一段固定提示（`:9-14`），内容止于「私密简历、通过专属链接打开」。措辞的边界是只讲链接、不讲鉴权：早期版本末尾跟着「无需注册，也无需输入密码」，等于对着访客描述后台的账号体系，一句用不上的信息，已删。

凭证的读写集中在 `utils/share.js`，只有两个 localStorage 键（`:9-10`）：

- `resume-share-token`：访客 JWT。
- `resume-share-version`：链接绑定的版本 ID，链接没绑版本时会主动 `removeItem`（`:18-21`），避免残留上一个链接的版本。

后端返回体里的 `remark` 不落存储——备注只在后台用来区分链接，前台没有任何读取方。`clearShareAccess()` 由 request 拦截器在 401 时调用，两个键一起删（`:30-33`）。

## 首屏加载：两层 Promise.all

`ResumeHome.vue` 的数据获取分两条并行链（`onMounted`，`:337-349`）：

```js
await Promise.all([loadAll(), loadConfigAndReport()])
```

内层 `loadAll()`（`:263-279`）再开一个 `Promise.all`，六个内容接口一次发出，每个都带 `versionId`：profile、educations、experiences、skills、honors、portfolios（对应 `api/index.js:6-24`）。回来后逐个 `res.data || {}` / `|| []` 兜住。

外层那条链 `loadConfigAndReport()`（`:281-318`）做三件事：读站点配置、按条件查版本列表、上报访问。三个细节值得记：

- 配置只取三个字段：`siteTitle`、`defaultTheme`（交给主题初始化）、`aiEnabled`，并把 `siteTitle` 同步到 `document.title`（`:285-292`）。配置接口失败时 catch 里只补一句 `themeStore.init('default')`（`:294`），标题保留 `index.html` 里的默认值。
- `getVersions()` 只在「持有管理员 token 且 URL 带 `?versionId=`」时才请求（`:298-306`）。访客侧永远不调，避免把版本列表暴露出去——这是页面级的防信息泄露，和后端强制以访客令牌绑定版本为准是两层独立保险。
- 访问上报用 `sessionStorage['resume-visit-reported']` 做标签页级的一次性标记（`:310-314`），配合 `localStorage['resume-sid']` 生成的会话 ID（`:254-261`）。sessionStorage 挡刷新和 HMR，localStorage 的 sid 让服务端在会话窗口（`app.visit.session-window-minutes`，默认 30 分钟）内认同一个会话。

`loading` 初值是 `true`，模板最外层是 `v-if="loading"` 的整屏加载态（`:41-47`），`finally` 里才置 false（`:344`）。原因写在 `:40` 的注释上：`HeroSection.vue:21-23` 对空数据有兜底文案（`暂未设置姓名`），没有这道门就会出现「兜底文案一闪然后被真数据替换」。副作用是所有接口都失败时页面也会渲染出空骨架，靠 `visible` 把板块全隐藏。

## 板块显隐由数据决定，不由配置决定

`ResumeHome.vue:198-212` 一个 computed 决定页面上有哪些板块：

```js
const visible = computed(() => ({
  about: Boolean(p.name || p.about),
  education: educations.value.length > 0,
  experience: hasWork || hasProject,
  experienceTarget: hasWork ? 'experience' : 'project',
  skills: skills.value.length > 0,
  honors: honors.value.length > 0,
  portfolio: portfolios.value.length > 0,
  contact: Boolean(p.github || p.gitee || p.csdn)
}))
```

没有「显示/隐藏作品集」这类开关。哪张表没数据，对应 `v-if` 就不渲染，也不会留「暂无」占位。`site_config` 里也确实只有站点标题、默认主题、AI 开关三项（见第 11 篇表结构）。

两个不太显眼但会影响观感的判定：

- 工作经历和项目经历共用 `experience` 表，前端按 `type` 拆（`:191-194`）：`type === 1` 算工作，`type === 2 || type == null` 算项目。后端新建记录时 type 有默认值 1，所以 `null` 分支只在数据是手写导入或历史遗留时才用得上。
- `contact` 板块只看三个代码仓库链接（github/gitee/csdn），邮箱电话在侧栏头像卡里显示，不算 contact 板块，所以只有邮箱时顶部导航不会出现「联系」。

顶部导航项由 `visible` 派生（`:217-226`），标签固定五个字：评价 / 经历 / 技能 / 荣誉 / 作品，其中「经历」的锚点在只有项目经历时指向 `#project`，有工作经历时指向 `#experience`（`experienceTarget`）。教育和联系在侧栏，不进导航。

`<aside class="side-column">` 放头像卡、技能、教育、联系，`<div class="content-column">` 放评价、工作、项目、荣誉、作品（`:68-120`）。两栏容器都只是布局壳，内容组件各自带 `v-reveal`。

## 滚动相关的三件事

**入场动画**是全局指令 `v-reveal`，注册在 `main.js:24-48`：`mounted` 加 `.reveal` 类，用 `IntersectionObserver`（`threshold: 0.06`、`rootMargin: '0px 0px -36px 0px'`）在元素进视口时补 `.reveal-in` 并 disconnect；不支持 IO 的浏览器直接加 `.reveal-in` 退化为无动画。`unmounted` 里再 disconnect 一次（`:45-47`），observer 挂在 `el._revealIO` 上。

样式在 `theme.css:126-138`：初始 `opacity: 0` + `translateY(26px)`，0.65s `cubic-bezier(0.22, 0.61, 0.36, 1)` 过渡到无位移。`prefers-reduced-motion: reduce` 时整段动画关掉（`:200-206`）；`.pdf-exporting .reveal` 强制可见（`:141-146`），这是导出截图能拿到完整内容的必要条件——否则视口外的板块在截图里是透明状态。

**导航高亮**（scrollspy）在 `ResumeHome.vue:321-335`，`rootMargin: '-42% 0px -52% 0px'` 把观察区域压成视口中间约 6% 高的横带，板块碰到这条带子就把对应板块的 id 写进 `activeSection`。绑定动作在 `onMounted` 的 `finally` 里、`await nextTick()` 之后（`:344-347`）——必须等空板块被 `v-if` 移除后再查 DOM，否则 `querySelectorAll('#xxx')` 会绑到已经不存在的节点。`onUnmounted` 里 `spyObserver?.disconnect()`（`:351-353`）。

**吸顶**：顶部导航 `position: sticky; top: 0; z-index: 900`（`:362-365`），背景是 `color-mix` 半透明加 `backdrop-filter: blur(16px)`。侧栏 `position: sticky; top: 74px`（`:566-568`），74px 是导航 60px 高度加余量；导出态会退回 `static`（`:779-782`），因为 html2canvas 截图时吸顶会让左栏内容重复出现在长图里。

## 主题：属性选择器 + CSS 变量

三套主题靠 `<html data-theme="default|dark|fresh">` 上的 CSS 变量切换，不是 class。定义见 `theme.css:7-8`（`:root, [data-theme='default']`）、`:32`、`:56`，写入动作在 `store/theme.js:29`：

```js
document.documentElement.setAttribute('data-theme', theme)
```

前台组件一律引用变量（`--color-primary`、`--color-bg`、`--color-surface`、`--color-text`、`--hero-gradient`、`--shadow-card`、`--tag-bg` 等），所以换肤不需要组件配合。三套主题的实际取值可以直接对照 `theme.css:9-28 / 33-52 / 57-76`，例如主色分别是 `#2563eb`、`#22d3ee`、`#059669`，页面底色 `#f5f7fb`、`#0b1120`、`#f3faf6`，正文色 `#1e293b`、`#e2e8f0`、`#1f2937`。

持久化与优先级写在 `store/theme.js:32-37`：`init(serverDefault)` 里 `saved || serverDefault`，键是 `resume-theme`（`:15`）。也就是说后台「主题与站点」页配的默认主题只对首次访问、或本地没手动选过主题的访客生效，选过就以本地为准。这个行为是有意的，否则站长改默认主题会把已有访客的偏好冲掉。

`components/home/ThemeSwitcher.vue` 是一个 `el-dropdown`，遍历导出的 `THEMES` 常量（`store/theme.js:9-13`），每项左边一个小圆点预览（渐变色在 `ThemeSwitcher.vue:31-35` 局部硬编码），点击就 `themeStore.apply(key)`。

有一类颜色没走变量，而是在组件里按主题 key 建映射表：

- `SkillsSection.vue:33-54` 给 `el-progress` 的 `:color` 传三段式色阶（60/85/100 分界），三套主题各一组。
- `ExperienceSection.vue:64-70` 给 `el-timeline-item` 的 `:color` 取主色。

这两处的颜色值和 `theme.css` 里的变量是重复信息，加第四套主题时要同时改三处（`THEMES` 常量、`theme.css` 调色板、这两个 map），没有机制保证不漏。

## 版式与响应式

桌面是「定宽容器 + 双栏栅格」：`.resume-main` `max-width: 1080px` 居中（`:539-543`），`.resume-layout` 是 `grid-template-columns: 264px minmax(0, 1fr)`、`gap: 18px`、`align-items: start`（`:546-551`）。`minmax(0, 1fr)` 里的 0 不是多余——不写右栏的 `min-width` 默认是 `auto`，长链接和 `white-space: nowrap` 会把栅格撑破。

单栏断点在 880px（`:669-735`），做法不是把两栏堆起来，而是让两个栏容器 `display: contents` 解除包裹，再由 `order: 1~9` 把九个板块按「头像 → 评价 → 工作 → 项目 → 技能 → 荣誉 → 作品 → 教育 → 联系」重新排进同一个 flex 流。这样双栏时的「左栏三块 + 右栏五块」在单栏下能插成合理顺序（技能从右栏位置挪到评价之后），而不是先出完左栏再出右栏。同时清掉 `.section-block` 默认的 `margin: 0 auto 18px`（`theme.css:219-222`），间距统一交给 `margin-top`——因为 flex 里相邻块的下外边距不再折叠。

`theme.css:299-305` 另有一个 768px 断点，只收紧 `.section-block` 的 padding 和左右边距；`ResumeHome.vue` 内部还有两处 768px 的局部规则（`:761-765`、`:811` 起）。也就是说移动端适配只有一个主断点加若干局部微调，没有做多档平板布局。

导出态的版式覆盖集中在 `:767-796`：`.resume-main` 宽度写死 1080px、`max-width: none`，栅格改成 `290px minmax(0, 1fr)` + `gap: 10px`，页脚隐藏。宽度写死的原因在第 07 篇推导分页高度时会看到——截图宽度必须是个常量，否则 A4 分页比例随窗口变化。

## 板块组件里的几个实现选择

**经历**（`ExperienceSection.vue`）按条数分两套渲染：只有一条时用普通卡片 `.single-item`，两条以上用 `el-timeline`（`:7-49`）。这个分支是为了避免「单条经历挂在一个时间轴点上」的尴尬观感。副作用是分页切片要同时认两种选择器（见第 07 篇的七个卡片选择器）。日期显示精简到 `yyyy.MM`（`toMonth`，`:77-82`），结束时间为空显示「至今」（`:84-92`）。技术栈按中英文逗号、顿号切成标签（`techList`，`:71-75`）。

**作品集**（`PortfolioSection.vue:88-122`）会测量描述是否真的溢出：`scrollHeight > clientHeight + 1` 的项才在卡片上给弹窗入口，测量时机有三处——`nextTick`、`document.fonts.ready`、resize 后 150ms 防抖。中文字体是异步加载的，字体落地前后行高会变，所以 `fonts.ready` 后要重测。

**荣誉证书**分两层：列表页 `HonorsSection.vue:44-49` 用 `router.push` 跳到 `/honor/:id`，并把当前版本 ID 放进 `query.v`；详情页 `HonorDetail.vue:98-113` 再取一次 `getHonors(query.v)`，然后从数组里 `find(id)`。没有做单条查询接口，等于把整份荣誉列表拉下来在前端挑一条。返回按钮 `goBack()`（`:93-96`）会把 `query.v` 还原成首页的 `?versionId=`。级别配色在两处各写了一遍相同的关键字判断（`HonorsSection.vue:52-59`、`HonorDetail.vue:79-86`：国家级/国际级归一档，省/高级一档，校/中级一档），属于可收拢但暂时重复的代码。

**头像卡**（`HeroSection.vue:8-15`）对空头像给一个图标占位，邮箱渲染成 `mailto:` 链接，只有邮箱和所在地进这张卡；联系方式板块只放三个仓库链接，两边分工不重叠。

## 网页版与导出态的一处口径差异

`theme.css:164-166` 在导出态隐藏 `#contact` 和 `#portfolio`，而首页里作品集板块本身就有 `id="portfolio"`（`PortfolioSection.vue:2`），PDF 一定不含作品。这是刻意的（作品集属于网页交互区），但只看 CSS 会以为漏掉了导出内容。

## 可复用点

- **路由守卫只判「有没有凭证」，有效性留给后端**：三条规则全部是 `localStorage` 存在性判断（`router/index.js:122-140`），没有任何一处解码令牌或比对时间。过期、吊销、次数用尽都由请求返回 401 后再由拦截器统一收口（第 02 篇）。这套分工的价值在于判定只有一份真相：令牌有效期规则改动时不用碰前端守卫；代价是首屏会先渲染骨架再被踢走，所以整屏加载态必须存在（`ResumeHome.vue:41-47`）兜住那一瞬。任何"前端提前判过期"的优化都会把同一套规则实现两遍。
- **板块显隐由数据条数决定，不配置开关**：`visible` computed 把「表里有没有数据」直接映射成 `v-if`（`ResumeHome.vue:198-212`），导航项再从 `visible` 派生（`:217-226`）。加一个板块只需要写组件 + 加一行 computed 字段，后台不需要多出七个布尔开关，`site_config` 因此能只有三项。适用条件是"空数据本来就不该显示"；一旦需求变成"内容存在但先隐藏"，就得补显式开关，别把两套口径混在同一个 computed 里。
- **一次性上报用 sessionStorage，会话归并用 localStorage**：`resume-visit-reported` 标签页级封顶（`ResumeHome.vue:310-314`），`resume-sid` 跨标签页与跨刷新存活（`:254-261`）。两个存储各挡一类重复——sessionStorage 挡刷新与 HMR 重复计数，sid 让服务端把同一会话的多次访问算一条。只留 sessionStorage 会把同一浏览器窗口的多次会话算成一个，只留 localStorage 会让刷新页面直接丢计数；这种"次数只记一次、但会话要能归并"的埋点场景两个都要。
- **滚动观察者类交互要等 `v-if` 结算完再绑定**：scrollspy 的初始化放在 `loading = false` 之后、`await nextTick()` 之后（`:344-347`），因为空板块会被 `v-if` 从 DOM 移除，绑早了就是把 observer 挂在不存在的节点上。`rootMargin: '-42% 0px -52% 0px'` 把观察区域压成视口中间约 6% 的横带（`:321-335`），比"元素顶部进视口就高亮"稳定得多——两个板块同时可见时不会来回跳。这套约定在别的项目同样成立：所有"绑 DOM 节点"的观察者都要挂在数据就绪之后，`onUnmounted` 里逐个 disconnect。
- **`display: contents` + `order` 重排双栏，比堆叠好看**：880px 断点让两个栏容器解除包裹（`:669-735`），九个板块由 `order: 1~9` 插进同一个 flex 流，技能从右栏位置挪到评价之后，而不是先出完左栏再出右栏。随之必须清掉 `margin: 0 auto 18px`（`theme.css:219-222`）把间距统一交给 `margin-top`，因为 flex 里相邻块的下外边距不再折叠——这是这个写法唯一的坑。另外两处颜色 map（`SkillsSection.vue:33-54`、`ExperienceSection.vue:64-70`）和 `theme.css` 变量是重复信息，加第四套主题要同时改三处且没有机制保证不漏，抄这套主题方案时最好先把颜色全收进变量。
- **访客可见文案只描述当前这条链路**：拦截页固定提示止于「私密简历、通过专属链接打开」（`BlockedHome.vue:9-14`），不提注册、不提密码。这类页面对象是拿着链接来的第一次访问者，把后台的账号体系写进提示不解决任何一步卡点，只会多出一层「原来还有别的入口」的推断；同理适用于报错文案，第 03 篇里链接绑定的版本被删后返回「该链接暂不可用，请联系站长更新」是同一条约束。约束落地的方式是文案只写"下一步做什么"，机制名词留在文档里。
