## 三、实体管理的统一 CRUD 模式

后台每个实体（教育、工作、技能、荣誉、作品集）的管理页面结构一样：

**列表页**：
```
顶部：新增按钮 + 搜索框（可选）
主体：el-table 展示所有记录
操作列：编辑按钮 + 删除按钮（二次确认）
```

**新增/编辑**：
```
点击新增/编辑 → 打开 el-dialog
弹窗内：el-form 表单，每个字段一个表单项
提交前：表单校验（必填、长度限制）
提交后：调后端接口 → 关闭弹窗 → 刷新列表
```

### 后端统一 CRUD 实现

**文件**：`backend/src/main/java/com/example/resume/service/`

每个 Service 继承一个通用模式：

```
class EducationService {
  // 列表（按 versionId 过滤）
  listByVersion(versionId)
    → educationMapper.selectList(
        new LambdaQueryWrapper<Education>()
          .eq(Education::getVersionId, versionId)
          .orderByAsc(Education::getSort)    // 按 sort 字段排序
      )

  // 新增
  create(dto)
    → entity = new Education(dto)
    → entity.setVersionId(currentVersionId)  // 强制当前版本
    → entity.setSort(nextMaxSort)            // 排序号 +1
    → educationMapper.insert(entity)

  // 更新
  update(id, dto)
    → 校验存在 + 版本匹配
    → 只更新非 null 字段（LambdaUpdateWrapper 或 @TableField(updateStrategy)）

  // 删除
  delete(id)
    → 校验存在 + 版本匹配
    → educationMapper.deleteById(id)
}
```

### sort 字段

所有排序内容（教育、工作、项目、技能）都有 `sort` 整数字段。新增时取当前版本该表的最大 sort + 1。前端提供上移/下移按钮：

```
下移:
  当前记录和 sort+1 的记录交换 sort 值
  后端 UPDATE 两条记录的 sort 字段（同一个事务）
```

**知识点**：sort 字段实现"手动排序"。`@TableField(updateStrategy = FieldStrategy.IGNORED)` 可以让 MyBatis-Plus 更新 null 值（默认会跳过 null），但通常不想传 null 就不传，保持默认策略即可。

## 四、简历版本切换器

**后台顶部**：始终有一个版本切换下拉框。管理员切换版本后：
1. `localStorage.setItem('currentVersionId', id)`
2. 刷新页面（或重新请求数据）

所有后台管理页面在进入时读这个值，用来做"当前操作的是哪个版本"的作用域限定。

---

## 五、分享链接管理

**后台页面**：表格形式列出所有链接。操作列：
- 复制链接（调后端生成完整 URL）
- 编辑（改备注、过期时间、最大访问次数、绑定版本）
- 吊销（enabled 置 0）
- 删除（硬删除，同时失效所有已经发出的访客令牌）

后端每次吊销/删除 → 该链接的 `enabled=0` → JWT 过滤器里每次访客请求都会回查这个字段 → 即时拦截。

## 六、站点配置（SiteConfig）

一个全局单例配置（id 固定为 1），存：
- 站点标题（HTML `<title>` 用）
- 站点副标题（首页 banner 用）
- 主题色
- 各板块显示/隐藏开关
- AI 聊天是否启用

前端启动时 `api.siteConfig.get()` 拉一次，存在 Pinia store 里，全应用共享。

### 版本变更后的配置同步

管理员创建新简历版本后，首页的站点配置自动复制到新版本（保证新页面和原页面一致）。

---

## 七、AI 问答记录（AiChatLog）

后台可以查看所有 AI 问答记录：谁问的（按 IP）、什么时候问的、问题和回答内容。默认分页 20 条。

主要用于：
- 观察访客关心什么问题（优化简历）
- 发现 AI 答非所问的情况（优化 Prompt 或知识库）

## 八、知识点总结

| 知识点 | 说明 |
|--------|------|
| 统一 CRUD 模式 | Service 层 list/create/update/delete 四个方法，配合 MyBatis-Plus BaseMapper 快速实现 |
| LambdaQueryWrapper | 用方法引用拼条件 `.eq(Education::getVersionId, versionId)`，避免硬编码字段名 |
| @Transactional 排序交换 | 上移/下移按钮其实是两条 UPDATE，必须在一个事务里 |
| @TableField(updateStrategy) | 控制 null 值在更新时是否忽略。FIELD 级别的策略 |
| 版本作用域 | 所有数据操作先 resolveVersionId，确保管理员在正确版本下工作 |
| Element Plus Form 校验 | :rules + prop 双向绑定，提交前 formRef.validate() 校验 |
| @RestControllerAdvice 全局异常 | BusinessException 被统一捕获成 {code, msg, data} 返回 |
| Knife4j / OpenAPI | 后端接口文档，访问 /doc.html 可以在线测接口 |
