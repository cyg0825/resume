# 功能三：AI 智能问答（RAG + 本地降级）

## 功能概述

简历右下角悬浮按钮弹出聊天面板。访客可以用自然语言提问，比如：
- "你好，你叫什么名字？"
- "你做过什么项目？"
- "你熟悉哪些测试工具？"

后端用 RAG（检索增强生成）方案：
1. 先把简历所有内容（个人信息、教育、工作、项目、技能、荣誉）切成知识片段
2. 每个片段用 Embedding 模型转成向量存在内存里
3. 访客提问时，把问题也转成向量，和所有片段算余弦相似度，取 top-N 最相关的
4. 把这些片段塞到 Prompt 里问大模型
5. 大模型基于提供的片段来回答，不会瞎编简历内容

如果 Embedding 或大模型都不可用（API 额度用完、网络问题），自动降级到本地关键词匹配 + 模板回答。

---

## 一、RAG 是什么

RAG（Retrieval-Augmented Generation，检索增强生成）是一种让大模型回答"私有知识"的方案。

**普通大模型的问题**：它的知识只到训练截止日，而且不知道某个具体的人的简历。直接问"简历主人做过什么项目"，大模型会瞎编。

**RAG 的思路**：
```
用户提问 → 检索私有知识库里相关片段 → 把片段 + 问题一起发给大模型 → 大模型基于给定片段回答
```

这样大模型只能用提供的片段来回答，不能瞎编简历里没有的内容。

---

## 二、Embedding 是什么

Embedding 把一段文字转成一个数字向量（比如 1024 维的浮点数数组）。语义相近的文字，转成向量后在向量空间里的位置也相近。

举个例子：
```
"你做过什么项目"  →  [0.12, -0.34, 0.56, ...]
"项目经历"        →  [0.11, -0.32, 0.55, ...]   ← 和上面很接近
"教育背景"        →  [0.89, 0.23, -0.45, ...]   ← 和上面很远
```

所以访客问"项目经历"时，系统算出它和所有知识片段的向量相似度，取相似度高的那些片段作为上下文。

### 用的模型

使用支持中文的 Embedding 模型，输出 1024 维向量。

### 调用方式

OpenAI 兼容格式：
```json
POST {AI_API_URL}/embeddings
{
  "model": "{EMBEDDING_MODEL}",
  "input": ["你好", "世界"]
}
```
返回 `{ "data": [{ "embedding": [0.12, -0.34, ...] }] }`。

## 三、向量检索：余弦相似度

两个向量的相似度用**余弦相似度**计算：

```
cos_sim(A, B) = (A·B) / (|A| × |B|)
```

- `A·B`：点积，A 和 B 各维度相乘再求和
- `|A|`：A 的模长（各维度平方和开根号）

结果在 [-1, 1] 之间。越接近 1 越相似。

**为什么用余弦而不是欧氏距离**？因为向量的模长会受"文字长度"影响（长文本 Embedding 出来的向量模长更大）。余弦只看方向，不受模长影响。

## 四、知识库构建（AiService.buildKnowledge）

**文件**：`backend/src/main/java/com/example/resume/service/AiService.java`

每次 AI 问答前检查知识缓存。如果当前版本的知识片段还没构建过，就现构建：

```
1. 调 ResumeVersionResolver.resolveVersionId(...) 确定版本
2. 查 DB 拿到该版本的全部内容：
   - Profile（姓名、职位、标语、自我介绍）
   - Education（每条学历记录）
   - Experience（工作经历 + 项目经历，每条）
   - Skill（每条技能组）
   - Honor（荣誉，不绑定版本，按姓名查）
   - Portfolio（作品集，不绑定版本，按姓名查）
3. 按模板拼成文本片段：
   - Profile → "个人简介：{slogan}。{intro}"
   - Education → "{年份} 在 {学校} 读 {专业}，{描述}"
   - Experience（工作）→ "{年份} 在 {公司} 做 {职位}。{描述}"
   - Experience（项目）→ "项目经历：{项目名}。{技术栈}。{描述}"
   - Skill → "技能：{分组名}。{条目}"
4. 去重（完全相同的片段只保留一份）
5. 把所有片段批量调 Embedding API 转成向量
6. 存到内存缓存：Map<Long, KbCache>，key 是 versionId
   KbCache 里有 List<String> texts 和 List<double[]> embeddings
```

**缓存策略**：版本不变时直接复用。版本变更后（创建/更新/删除）通过 `@EventListener` 触发清除——监听 `ResumeVersionChangedEvent`，把对应的 KbCache 从 Map 里移除。下次问答时自动重建。

**知识点**：Spring 的 `@EventListener` 机制是发布-订阅模式。Service 层在版本变更后 `applicationEventPublisher.publishEvent(new ResumeVersionChangedEvent(versionId))`，AiService 里 `@EventListener` 的方法自动收到通知。这种方式让版本服务和 AI 服务解耦——版本服务不知道有 AI 服务在监听它。

## 五、检索（retrieveContext）

```
1. 把访客问题调 Embedding API 转成向量
2. 遍历 KbCache 里的所有片段向量，算余弦相似度
3. 过滤掉相似度 < 0.4 的片段（完全不相关的不要）
4. 按相似度降序取前 5 条
5. 把 5 条文本拼成上下文返回
```

### 为什么要去重

工作经历有重复的项目也会被拆成多个片段。如果两个片段相似度非常高（>0.95），说明是重复内容，只保留一个。

## 六、调用大模型（callLlm）

**模型**：中文大语言模型（OpenAI Chat Completions 兼容接口）

**System Prompt**：
```
你是简历主人的介绍助手。所有回答必须基于给定的简历信息片段。
如果片段里没有相关内容，诚实说"简历里没有提到这方面的信息"，不要瞎编。
保持口语化、简洁友好。
```

**User Prompt**：
```
以下是简历的相关片段：
{检索到的 5 条片段拼接}

访客问题：{question}
```

用 Java HttpClient 发送 HTTP 请求，OpenAI 兼容格式：
```java
HttpRequest.newBuilder()
    .uri(URI.create(System.getenv("AI_API_URL") + "/chat/completions"))
    .header("Authorization", "Bearer " + apiKey)
    .POST(HttpRequest.BodyPublishers.ofString(bodyJson))
    .build()
```

**知识点**：Java 11 引入 `java.net.http.HttpClient`，是官方 HTTP 客户端，替代 Apache HttpClient 和 OkHttp。它是异步优先的（`sendAsync` 返回 CompletableFuture），本项目用的是同步 `send`。Body 用 `ofString` 直接传 JSON 字符串，header 用链式调用。

### 速率限制

大模型 API 有调用频率限制。后端用 `SimpleRateLimiter`（本地内存实现的令牌桶）限制：每个访客 IP 每分钟最多 10 次请求，管理员 IP 不限。

**知识点**：令牌桶算法——每个 IP 有一个"桶"，初始容量 N，每秒补充 M 个令牌。每次请求消耗一个令牌。桶空了就拒绝。用 `ConcurrentHashMap<String, RateState>` 存每个 IP 的状态，`synchronized` 保护并发。

## 七、本地降级回答（localAnswer）

当 Embedding 或大模型调用失败时启用。

### 匹配逻辑

```
1. 把访客问题里的常见词（姓名、简历、你）去掉，提取关键词
2. 遍历所有知识片段，统计每个片段包含多少个关键词
3. 关键词命中数 ≥ 2 的片段被选中，或者关键词命中数是全局前 3 的片段
4. 把选中的片段拼成回答，开头加一句"根据简历信息，"
```

### 完全没匹配到时的兜底

```java
// 从个人简介里拼一个通用自我介绍
String profileIntro = "你好，我是{姓名}，{职位}，{slogan}。";
```

虽然比不过大模型的自然度，但能保证：
- API 挂了系统还能用
- 不用完全依赖外部服务
- 没有泄露任何隐私（片段都来自公开简历本身）

## 八、前端聊天界面

**文件**：`frontend/src/components/home/AiChatWidget.vue`

### 交互设计

- 右下角悬浮圆形按钮，点击弹出面板
- 面板顶部：标题 + 关闭按钮
- 中间：消息列表（滚动到最新）
- 底部：输入框 + 发送按钮 + 4 个快捷问题（"你好"、"你做过什么项目"、"你的技能"、"教育背景"）
- 移动端自动隐藏（避免遮挡小屏）

### 会话管理

用组件内的 `messages` 数组存当前会话，不持久化。刷新页面重置。每次发送消息：
1. 立即把问题加到 messages
2. 输入框禁用，显示"思考中..." loading
3. `POST /api/ai/chat`（body: `{question}`）
4. 拿到回答后 append 到 messages

### 打字效果

回答到达后用 `typingText(answer)` 逐字显示，每 30ms 加一个字符。提升观感。

## 九、知识点总结

| 知识点 | 说明 |
|--------|------|
| RAG | 检索增强生成，把私有知识片段检索出来塞给大模型，让它只能在给定范围里回答 |
| Embedding | 把文字转成向量，语义近的向量位置也近。用余弦相似度衡量距离 |
| 余弦相似度 | 两个向量点积除以模长乘积，不受向量模长影响 |
| 向量缓存 | Map 存每个版本的知识库向量，版本变更时通过 @EventListener 清除 |
| Spring Event | 发布-订阅解耦，一个模块 publish，另一个模块 @EventListener 接收 |
| Java HttpClient | Java 11+ 官方 HTTP 客户端，支持同步/异步/WebSocket |
| 令牌桶限流 | 本地内存实现，按 IP 限制 API 调用频率 |
| 降级策略 | Embedding 失败 → 关键词匹配；大模型也失败 → 模板兜底回答 |
| 并发安全缓存 | ConcurrentHashMap 作为内存缓存，synchronized 保护并发修改 |
